### 概要と目的

このドキュメントは **屋内ダンジョン画像生成仕様書** です。  

mapgen_world.md のワールドマップ画像生成仕様をベースに、屋内ダンジョンマップ画像生成の仕様を定義します。

- 1ピクセルが、1ブロック（1キャラと同サイズ）に対応する、2D RPGのダンジョンマップの画像を生成することを目的とします。
- 真上から見下ろしたトップビューのダンジョンマップ画像を生成します。
- レトロな2D RPGのように、1ブロックは、床、壁、通路、絨毯などのバイオームで構成されます。
- バイオーム色は「単色」です。色とバイオームは1対1で対応します。
- この画像を更に加工して、最終的なゲームのハイトマップやテクスチャマップを生成することを想定しています。
- 出力は png 画像です。バイオームを色分けして表示します。

---

### データモデルとフォーマット

#### png 画像
- 160x160ピクセルを標準とし、128x128～1024x1024までの範囲で生成可能です。
- 1ピクセルが、1ブロックに対応します。

#### バイオーム
**mapgen_world.md** の `MapGenBiomeID` と同じ数値を使用しますが、ダンジョンマップでは `PLAIN` が床、`MOUNTAIN` が壁、`ROAD` が通路、`BRIDGE` が絨毯などの意味に置き換えて使用します。
```cpp
enum MapGenBiomeID
{
	FLOOR1 = 0,			//	標準的な床
	FLOOR2 = 1,			//	ひび割れた床や、模様のある床などのバリエーション
	UPPERFLOOR = 2,		//	部屋の中にある1段上にある床。王の間のような使い方。
	WALL = 3,			//	通行不能
	INNERWALL = 4,		//	壁の内側。上からは真っ黒に見える。
	CORRIDOR = 5,		//	通路
	DOOR = 6,			//	部屋の入り口に配置される扉
};
```

### DungeonMapImageGenerator 仕様

#### sample/dungeon内の画像を元に、屋内ダンジョンの部屋、通路の作りについて特徴を分析し、仕様化する。
- 全体は「黒背景上に独立した部屋群」を配置し、部屋同士を通路で接続する構造が基本。
- 部屋の形は長方形主体だが、中央広間や祭壇部屋では段差・内壁・水路でシンメトリを作る例が多い。
- 部屋サイズは小部屋(12x12～20x20)、中部屋(20x20～32x32)、広間(32x32～56x56)が混在する。
- 通路は4ブロック幅が中心で、幹線やボス導線のみ8ブロック幅になる。
- 曲がりは90度主体で、直線通路 + T字/十字ジャンクションでネットワーク化される。
- ドアは部屋境界に集中し、1部屋あたり1～4箇所。重要部屋の扉は複数設置されやすい。
- 水路/溶岩/穴などの通行阻害タイルが一定確率で差し込まれ、橋・飛び石・狭路で再接続される。
- 罠部屋、墓所、宝物庫、玉座部屋など「役割付きの部屋」が点在し、装飾密度に強弱がある。
- 外周は壁で閉じることが多いが、入口ホールや上下階段に向かう軸線は明確に確保される。

#### 目標地形
- sample/dungeon 内の画像を参照。これらの画像のような、変化にとんだトップビューのダンジョンマップ画像を生成することを目標とする。
- 部屋は1～4個の入口を持ち、通路または隣接開口で連結される。
- 通路は直線と直角折れを基本とし、対称型レイアウトでは十字導線を優先する。
- 一定確率で、一本の直線通路に沿って2～4部屋が規則的に並ぶサブ構造を生成する。
- 上記サブ構造の部屋配置は、通路の左側のみ・右側のみ・左右交互のいずれかを抽選する。
- 上記サブ構造では、隣接する部屋同士は1ブロック壁で隔て、部屋サイズはほぼ同一（まれに軽微な不揃い）にする。
- 上記サブ構造の扉は「部屋-壁-通路」の壁セルに置き、部屋同士を直接つなぐ扉は作らない。
- 部屋サイズは 12x12～56x56 の範囲で、用途に応じて小部屋/広間を混在させる。
- 壁厚は原則1ブロック。内壁や壇上を使う部屋では2ブロック相当の厚みを部分的に許容する。
- 扉は原則1x4または4x1(向き依存)で、行き止まり軽減と導線制御のために設置する。
- 通行阻害(池・溶岩・穴・瓦礫)は局所的に配置し、通路ネットワークを完全分断しない。
- ランダム性が高く、生成のたびに毎回違った意外性のある地形が生成される。
- マップは壁で埋まっており、それをくり抜くように部屋や通路を生成する。
- 一定確率で、左右対称の部屋ペアを2～4組生成する（完全一致ではなく約8割対称）。
- 一定確率で、X軸中央をまたぐ部屋を1～3個生成する。

#### 生成アルゴリズム概要
- 下記の 10 ステップで生成し、最終的に MapGenBiomeID の2D配列へ確定する。

1) レイアウトモード決定
- seed から構図モードを抽選する。
	- hub: 中央広間 + 放射状接続
	- ring: 輪状の部屋配置 + 内側部屋群
	- branch: 幹線 + 枝分かれ部屋
- モードごとに有効通路幅・有効ループ率・有効枝率を補正して、構図差を強調する。

2) ソリッド初期化
- 全セルを WALL(3) で埋める。
- マップ外周1～2セルを安全マージンとして保持する。

3) 部屋シード配置
- roomRate と roomSize から目標部屋面積を算出し、矩形部屋を非重複で配置する。
- 小部屋/中部屋/大部屋を重み付き抽選で混在させる。
- 一定確率で王座部屋・宝物庫・罠部屋などの役割タグを付与する。
- 一定確率で左右近似対称の部屋ペア（2～4組）を先行配置し、全体の構図に反映する。
- 一定確率でX軸中央をまたぐ部屋（1～3個）を先行配置する。
- 一定確率で直線通路沿いの規則部屋ブロックを先行配置する。

4) 部屋整形
- 角欠け、柱、内壁、壇上(UPPERFLOOR)を追加して単純な矩形感を弱める。
- 壁厚1を維持しつつ、重要部屋のみ内側リング(擬似二重壁)を許可する。

5) 接続グラフ生成
- 各部屋の中心/扉候補をノード化し、近傍グラフを作る。
- 最小全域木で全接続を保証し、追加辺でループ率(loopRate)を付与する。
- 行き止まり率(deadEndRate)を制御するため、枝道ノードを一部追加する。
- hub ではキー部屋に重みを寄せた接続スコアと4象限スポーク補強を行う。

6) 通路掘削
- A*またはL字優先ルーティングで通路を掘る。
- 部屋同士の接続では、まず直線接続可能かを判定し、可能な場合は直線通路を優先する。
- 直線接続が不可能な場合のみL字接続を選択し、曲がり角は部屋壁との干渉が少ない候補を優先する。
- 非直線接続では、扉位置を角から少し離した候補へ再調整できるかを優先的に確認する。
- 非直線かつ接続維持に必須でない追加通路は、部屋が孤立しない条件を満たす場合に生成をキャンセルする。
- 通常通路は4ブロック幅で掘削する。
- 中心部をつなぐ幹線のみ8ブロック幅で掘削する。
- 外周を一周する強制リング通路は生成しない。
- 直線通路沿いの規則部屋ブロックが選ばれた場合は、一本の主通路を明示的に掘り、各部屋へ短い接続通路を追加する。
- linearWing 構造は、孤立を防ぐために少なくとも1本は既存の通路ネットワークへ接続する。
- 通路セルは部屋矩形の内部セルを上書きしない（通路が部屋内部を貫通しない）。
- 通路バイオームは CORRIDOR(5) を使用する。

7) 扉配置
- 部屋境界と通路接続点に DOOR(6) を配置する。
- doorRate と keyRoomDoorBias で一般部屋/重要部屋の扉数を制御する。
- 隣接扉過密を避けるため最小間隔(doorMinInterval)を設ける。
- 扉数の目安は、通常部屋1・大部屋2・広間/ハブ部屋3～4とし、上限超過となる接続追加は抑制する。
- 扉は部屋の壁ライン上に配置し、向きは X軸扉で4x1、Y軸扉で1x4 を基本とする。
- 壁と扉の間に隙間ができないよう、扉セルは壁セルを置換する形で配置する。
- linearWing 構造で生成された部屋は、面している主通路側にのみ扉を配置し、同一構造内の部屋同士を直接つなぐ扉は作らない。

8) 障害地形とギミック配置
- 水路・溶岩・穴・瓦礫を部屋または通路脇に配置する。
- 導線を完全遮断しないよう、迂回路または橋セルを同時生成する。

9) 接続性修正と品質ゲート
- 入口セルから全主要部屋への到達可能性を検証。不達は通路再掘削で修正。
- 通路密度、部屋密度、行き止まり率、ループ率が目標レンジ外なら再調整する。
- 1セル孤立床や不自然な細切れ壁をモルフォロジーで除去する。

10) 最終量子化と出力
- 優先順位で確定: DOOR > CORRIDOR > UPPERFLOOR > FLOOR2 > FLOOR1 > INNERWALL > WALL
- 通常の生成フローで配置された部屋床は FLOOR1、構造指定（直線通路規則部屋・対称部屋）で配置された部屋床は FLOOR2 で塗り分ける。
- MapGenBiomeID 配列を色テーブルに変換して PNG 出力する。

- `linearWingRoomMin/linearWingRoomMax`: 2/4（規則部屋数レンジ）
- `linearWingAxis`: 0（0=auto, 1=Y方向主通路, 2=X方向主通路）

- `mirrorXChance`: 0.45（X軸近似対称構図の生成確率）

- `mirrorXRoomCount`: 0（0=自動、1～10で mirrorX 構造由来の部屋数目安）
- `defaultJitter`: 0.12（-p未指定パラメータへ適用するランダム揺らぎ率）

### ファイル構成とコードテンプレート

#### 以下の仕様については、既に作成されている WorldMapImageGenerator.(h|cpp) と同じ仕様にする。

#### ファイル構成
- `doc/mapgen_dungeon.md`（本仕様）
- `src/MapImageGenerator.h`（基底クラス。必要に応じて関数を追加）  
- `src/DungeonMapImageGenerator.(h|cpp)`（基底クラス。必要に応じて関数を追加可）
- `src/utils.(h|cpp)`（Worley/Perlin/quantizeの実装。必要な機能を要生成）
- `src/main.cpp`（exeのエントリーポイント。入力からパラメータを取ったり、出力をしたり、png画像を生成する。必要な機能を要生成）
- `src/CMakeLists.txt`（CMakeビルド設定。必要に応じて生成）
- `src/build.bat`（ビルド用バッチファイル）
- `src/build/mapimggen.exe`（ビルドで生成される実行ファイル）
- `src/include/*`（ライブラリヘッダー。zlib,lpng等）
- `src/lib/*`（スタティックライブラリ）
- `bat/*`（ビルド、テスト用バッチファイル。必要に応じて生成）
- `/mapimggen.exe`（ビルドで生成される実行ファイル。bat/build.batによって生成）

#### MapImageGeneratorクラス
- MapImageGeneratorクラスは、マップ画像生成の基底クラスです。
- DungeonMapImageGeneratorクラスは、MapImageGeneratorクラスを継承して、ダンジョンマップ画像生成の具体的な実装を行います。
- main.cpp では、コマンドライン引数を解析して、DungeonMapImageGeneratorクラスのインスタンスを生成し、マップ画像を生成し、ファイル出力します。

#### テスト出力ディレクトリ
- `out/$session/$index_*.*`（自動テストとサンプル出力。1セッションで複数の出力）

#### mapimggen.exe のコマンドライン仕様

```
mapimggen.exe -type dungeon -w 128 -d 128 -seed 12345 [extra options] -dir tmp/mapgen/ -out filename [--data --png --report]
```

- `-type` : マップ生成器の種類。今回は `dungeon`で、`world`, `cave` なども追加されていく。
- `-w` : マップの幅（ブロック単位）
- `-d` : マップの奥行き（ブロック単位）
- `-seed` : 乱数シード。未指定の場合はランダム値を使用する。
- `[extra options]` : 追加パラメータ。`-p paramName=value` の形式で任意のパラメータを指定できる。
- `-dir` : 出力ディレクトリ。未指定の場合はカレントディレクトリに出力される。
- `-out` : 出力ファイル名。未指定の場合は `out` が使用される。
